# SM-A556E (a55x) offline port record — kernel 6.1.157-android14-11

Target: Samsung Galaxy A55 5G, model `SM-A556E`, platform `a55x`
(Exynos s5e5545). This record documents the complete offline port of the
CVE-2026-43499 exploit payload and the KernelSU late-load selection from
the user-supplied `boot.img.lz4`. **No hardware validation has been
performed yet**; every device-facing claim below is static evidence from
the boot image unless explicitly marked pending.

## 3. Derived non-symbol constants

### ashmem_misc

`ashmem_misc` is absent from this kernel's kallsyms. It was recovered
from `.data` by scanning for a qword equal to `&ashmem_fops` and
validating the surrounding `struct miscdevice` (name pointer to
`"ashmem"`, minor `MISC_DYNAMIC_MINOR`). Exactly one candidate exists:

```text
ashmem_misc           = 0x02464420
miscdevice.fops       = 0x10
ASHMEM_MISC_FOPS_OFF  = 0x02464430
```

### nfulnl_logger.name

The first qword of `nfulnl_logger` (0x022d29e0) reads back as a pointer
to the `"nfnetlink_log"` string at `0x016ca0d5`; both the leak anchor
(`SLIDE_NFULNL_LOGGER_NAME_OFF`) and the object address
(`SLIDE_NFULNL_LOGGER_OBJECT_OFF`) use these verified values.

### random_table boot_id entry

`struct ctl_table` is not retained in this kernel's BTF. The layout was
recovered empirically: entry stride `0x40`, `procname` at `0x0`, `data`
at `0x8`. Walking `random_table[]` finds `boot_id` at index 4
(`0x0241e870`) and its `.data` slot at `0x0241e878`, whose value points
exactly at `sysctl_bootid` (`0x026b0518`) — the verification required by
the porting procedure before accepting `SLIDE_RANDOM_TABLE_BOOT_ID_DATA_PTR_OFF`.

### Tracefs event id

`__TRACE_LAST_TYPE` is 20 on this android14-6.1 kernel.
`__event_sched_blocked_reason - __start_ftrace_events = 0x2b0`, so the
zero-based index is `0x2b0 / 8 = 86` and the runtime event id is
`20 + 86 = 106` (`SLIDE_TRACEFS_EVENT_ID`). This matches every other
device-tested 6.1 profile in the repository.

### worker_thread caller

Capstone disassembly of `worker_thread` from the raw Image finds the
blocking `bl schedule` at `0xffffffc0080dbc90`; the saved caller is the
following instruction, `0xffffffc0080dbc94`:

```text
SLIDE_TRACEFS_WORKER_CALLER_OFF = 0x000dbc94
```

For comparison, the S24 FE profile records `0x000dbd9c` for the same
6.1.157 release in a different SoC tree — the values differ as expected,
so the A556E value was not copied.

### selinux_state.enforcing

`selinux_state` is reached indirectly (`sb->s_fs_info->state`), so the
enforcing offset was cross-checked through both accessor paths:
`sel_read_enforce` performs `ldrb w3, [x8]` and `sel_write_enforce`
performs `strb w8, [x21]` — both use displacement `0x0` against the
state pointer. Therefore `SELINUX_ENFORCING_OFF = selinux_state + 0 =
0x025c92f8`.

## 4. BTF layouts

The BTF blob required normalization: several structs (for example
`file_operations`, `rt_mutex_waiter`) emit member offsets scaled by 8
while `BTF_INFO_KFLAG` is 0. All member offsets below were normalized
(`/8`, non-byte-aligned values rejected). Key results:

```text

  llseek 0x08, read 0x10, write 0x18, read_iter 0x20, write_iter 0x28,
  unlocked_ioctl 0x50, compat_ioctl 0x58, mmap 0x60, open 0x70,
  release 0x80, splice_read 0xc8, show_fdinfo 0xe0

task_struct (size 0x12c0)
  usage 0x40, prio 0x84, normal_prio 0x8c, sched_task_group 0x348,
  pi_lock 0x924, pi_waiters 0x938, pi_top_task 0x948, pi_blocked_on 0x950

struct page (size 0x40)
  compound_head 0x08, slab_cache 0x18, page_type 0x30

struct rt_mutex_waiter (size 0x58)  ->  COMPACT_RT_MUTEX_WAITER 1
  tree_entry 0x00, pi_tree_entry 0x18, task 0x30, lock 0x38,
  wake_state 0x40, prio 0x44, deadline 0x48, ww_ctx 0x50
```

The compact 6.1 waiter layout is decisive: this s5e5545 tree does not
carry the reworked non-compact waiter that the S24 FE (`essi-S721N`)
profile uses, despite the identical release string. The A556E profile
therefore follows the device-tested 6.1 compact family
(e2s/e1s/e3q): `COMPACT_RT_MUTEX_WAITER 1`, `SLIDE_PSELECT_WORD_SHIFT 3`,
`SKB_DATA_DELTA -0x1000`, `MM_STRUCT_SZ 0x400`.

## 5. Physical load addresses

`text_offset` is 0, so the Image expects to load at `PHYS_OFFSET`.
`P0_PHYS_OFFSET` and `P0_KERNEL_PHYS_LOAD` are set to `0x80000000`.
**CONFIRMED** by static analysis of the a55x sboot.bin
(`A556EXXSGDZG2`): the branch immediately after the
`Starting kernel...` print does

```text
adrp x8, <g_slot page>; ldr w8, [x8, #g_slot]   ; slot var @ sboot file 0x482cf8
mov  w9, #0x80000000
mov  w0, #0xa0000000                            ; x0 = DTB physical address
add  x8, x8, x9
blr  x8                                         ; kernel entry = base + slot
```

and the slot variable is written by the EL3 handshake as
`(SMC 0xC200101C ret & 0x1F) << 16` (`ubfiz w8, w8, #0x10, #5` after the
`smc #0` at sboot file 0x2fb20), i.e. one of 32 64 KiB-aligned slots
spanning `[0x80000000, 0x801F0000]`. This mechanism is exactly why the
P0 oracle carries a 32-entry fingerprint table with a `0x10000` stride:
the slide scan resolves the runtime slot after load, so no device-side
modification of `P0_KERNEL_PHYS_LOAD` is needed.

## 6. P0 fingerprint table

`p0_fingerprint.h` was generated from the raw Image: for every candidate
slide `0x000000` through `0x1f0000` in steps of `0x10000`, the eight
little-endian qwords at page offsets `0x000, 0x200, ..., 0xe00` were
recorded (32 rows, all 256 source qwords read back from the Image).

The support feed entry references `ksud-samsung-android14-6.1-kdp`.
Before hardware use, run the standing checks from
[`kernelsu/README.md`](../kernelsu/README.md) against the recovered A556E
ELF: `kernel/check_symbol` on this target's `vmlinux.elf`, the
manual-relocation audit (`audit_module_against_target.py
--manual-relocation`), and `modinfo` vermagic equality. The generic pair
is build-verified for 6.1 but the KDP/RKP/DEFEX behaviour of the s5e5545
tree (Exynos 1480) is not hardware-proven; if the module panics in EL2
during live text patching, rebuild with
`CONFIG_KSU_SAMSUNG_NO_PATCH_TEXT=y` as the A56/A36 ports did.
